The log of everybody who tried to get in.

What it does

The capabilities

Every panel below is served by the real API of this project — nothing here is a mock-up.

⌨

A shell that answers

The commands of a small fake system are answered, so an attacker can walk in and believe it.

👤

Every login is kept

The user and the password of every attempt are written into the log of the session.

▤

The commands are kept too

Every command of every session lands in the log, with the address it came from.

⛓

No sessions mix

The events are collected under a lock, so two sessions never write into the same list.

⏱

Silent sessions end

A session that stops talking is closed instead of being kept open for ever.

⛁

A log you can read

The run writes plain JSON lines, one event per line, with no lock-in of any kind.

Architecture

How it works

The honeypot is a threaded socket server that writes a banner, asks for a user and a password and then answers the commands of a small fake system, so an attacker walks into a sandbox that is not a real machine. The events of every session are collected by the server under a lock, so two sessions never write into the same list. A session that says nothing is closed, and the log of the run is written as JSON lines.
