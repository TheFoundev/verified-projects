Trigger a build, watch the steps finish.

A self-hosted CI server in miniature: a small YAML subset parser for pipeline steps, build records with status and logs, trigger and run endpoints, and an in-memory build queue.

Open the console How it works
This is a Go CI service, not a hosted product. It is part of the Foundev portfolio: a self-contained repository with its own tests and README. The page you are reading is a project console — the numbers below are computed from the repository, and the demo runs the project's own command.
What it does

The capabilities

Every panel below is served by the console's real API — nothing here is a mock-up.

⌗

A YAML subset parser

Pipeline steps are parsed without a YAML dependency.

⇄

Trigger and run endpoints

A webhook-style trigger creates a build and runs its steps.

▤

Build records with logs

Every build keeps its status and the log lines produced by each step.

◷

An in-memory queue

Builds are queued and executed in order.

◫

Runs without Docker

The pipeline model and execution are local; no container runtime is required.

Architecture

How it works

main.go starts the HTTP server, server.go holds the build queue, the parser and the endpoints. The CSV stack names a real container runner and SQLite persistence; this build keeps builds in memory and simulates step execution, which the README states plainly. The Go test suite covers parsing, triggering and status transitions.
