What it does

The capabilities

Every panel below is served by the console's real API — nothing here is a mock-up.

⚖

Three-party escrow

Buyer, seller and an arbiter settle in native ETH or a single ERC20, with partial funding before the deadline.

⛓

An explicit state machine

Created, Funded, Released, Disputed, Refunded and ArbiterDecided, each with custom errors and full event coverage.

○

Pull payments only

There are no direct sends anywhere; checks-effects-interactions and ReentrancyGuard protect withdraw().

◈

Tokenized provenance

The ERC721 records the original creator, escrow link and audit verdict for every token.

⏱

Timeouts that settle

A silent seller, buyer or arbiter cannot strand the funds; the deadline paths release or refund.

⌗

A queryable factory

Deployed escrows are indexed by creation order, buyer and seller, with pagination on chain.

Architecture

How it works

The contracts compose access control, pausability, safe ERC20 transfers and the ERC721 implementation from OpenZeppelin rather than re-implementing them. EscrowFactory deploys escrow instances and maintains the index; the test-only attacker contract proves that withdraw cannot be re-entered. A Hardhat and TypeScript suite exercises funding, disputes, both timeout paths and the provenance record.
