Ingest clicks, validate the schema, aggregate the windows.

A Kafka-inspired event pipeline: a producer with delivery callbacks, schema-validating deserialisation with a dead-letter queue, windowed Kafka Streams aggregations and a materialized view server.

What it does

The capabilities

Every panel below is served by the console's real API — nothing here is a mock-up.

⇉

Deterministic click events

ClickProducer keys every event by session and generates stable event ids, in burst or continuous mode.

⛨

Schema enforcement

A Schema Registry compatible client validates every record and routes violations to clicks-dlq.

◷

Windowed aggregations

Tumbling one-minute windows, bot filtering and sessionization live in Kafka Streams state stores.

⌕

A materialized view

A JDK-only HTTP server exposes page, session and referrer statistics from the state store.

▤

A bundled dashboard

The project ships a responsive single-page dashboard with auto-refresh and no CDN dependencies.

◫

One-command local stack

Docker Compose brings up a KRaft broker, registry, producer, streams app and view server.

Architecture

How it works

Clients POST click events; the producer publishes to the clicks topic keyed by session. A validating deserializer checks each record against the bundled JSON Schema and diverts bad records to the DLQ. ClicksStreamsApp filters bots, aggregates page views in tumbling windows and writes to named state stores. ViewServer reads those stores (or the changelog topics in standalone mode) and serves the dashboard.
