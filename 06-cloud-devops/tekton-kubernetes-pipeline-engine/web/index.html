Resolve runAfter, then execute in order.

A Kubernetes-native pipeline engine in miniature: task and pipeline definitions with parameters, runAfter dependency resolution, validation of missing references, and execution status for every task.

Open the console How it works
This is a Go pipeline engine, not a hosted product. It is part of the Foundev portfolio: a self-contained repository with its own tests and README. The page you are reading is a project console — the numbers below are computed from the repository, and the demo runs the project's own command.
What it does

The capabilities

Every panel below is served by the console's real API — nothing here is a mock-up.

⌗

Typed task definitions

Tasks and pipelines carry parameters and references, parsed from the project format.

⇄

Dependency resolution

runAfter edges become an execution order, with cycles and missing tasks rejected.

◈

Validation first

A pipeline that references an unknown task fails before anything runs.

✓

Per-task status

Every task reports its outcome, so a run is inspectable end to end.

◫

Runs without a cluster

The resolver and executor are local; no API server or pod is required.

Architecture

How it works

engine.go parses the definitions, validates references, topologically orders the tasks and executes them, recording a status per task. main.go exposes the CLI. The CSV stack names Kubernetes, CRDs and kubectl; this build implements the resolver and executor locally, and the README is explicit that there is no API server or pod execution behind it.
