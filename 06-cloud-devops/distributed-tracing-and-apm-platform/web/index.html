Every span of a request, assembled into a trace.

Spanline keeps the spans of instrumented services in memory and groups them by trace id. A trace gets its total duration from the earliest start and the latest end of its spans, and the span without a parent is the root of the tree. For every service the store counts the spans and computes the p50 and the p95 of their duration in milliseconds. Spans arrive as JSON, also in the shape of the OpenTelemetry protocol.

What it does

The capabilities

Every panel below is served by the real API of this project — nothing here is a mock-up.

⌗

Spans with parents

A Span holds its trace id, its span id and the id of its parent, so the tree of a trace can be rebuilt.

◈

Trace assembly

Store.Traces groups the spans by trace id and computes the duration from the earliest start and the latest end.

⚖

Percentiles

Percentile sorts the durations of a service and takes the index int(p/100*(n-1)).

◑

Per-service latency

Store.Stats counts the spans of every service and gives their p50, their p95 and their errors.

⇄

Two ways in

IngestHandler takes a JSON array of spans and OTLPHandler takes the resourceSpans and scopeSpans of the protocol.

▤

Trace lookup

TraceHandler answers one trace by its id and answers 404 when there is none.

Architecture

How it works

tracing.go holds the model and the store. Span carries a trace id, a span id, a parent id, a service, an operation, a start, a duration and a status; Store keeps the spans in a slice behind a sync.RWMutex and Add appends to it. Traces groups the spans by trace id, takes the earliest start and the latest end for the duration, counts the spans with the status error and names the span without a parent as the root. Percentile sorts a slice of milliseconds and takes the index int(p/100*(n-1)). Stats groups the spans by service and fills a ServiceStats with the number of spans, the p50, the p95 and the number of errors. IngestHandler reads a JSON array of spans, OTLPHandler walks resourceSpans, scopeSpans and spans of the protocol, StatsHandler answers the latency and TraceHandler answers one trace of a /traces/{id} path. main.go fills the store with the four sample spans and serves the handlers on the address of the -listen flag.
