A small cluster you can actually operate.

Idempotent bootstrap scripts, systemd health and backup timers, a stateful Helm chart and an offline validation gate for a fault-tolerant K3s cluster on VMs and Raspberry Pis.

What it does

The capabilities

Every panel below is served by the console's real API — nothing here is a mock-up.

⌗

Numbered, idempotent bootstrap

Scripts 00 to 99 install the first server with cluster-init and join the rest with a token, safely on re-run.

⛭

Self-healing timers

A systemd health probe restarts a wedged runtime; a snapshot timer keeps etcd backups with retention.

◫

A real Helm chart

edge-stateful runs Postgres and a cache on local-path with headless services, PD, topology spread and NetworkPolicy.

◐

Mixed hardware

Agents are labelled node-class=pi or vm, with arm64 and low-memory overrides in values.pi.yaml.

⛨

An offline validation gate

YAML parsing, chart structure, storage checks, a secret scan and destructive-command guards run without a cluster.

▤

The runbook

Rollout, rollback, troubleshooting and backup restoration are documented for the operator on call.

Architecture

How it works

Three K3s servers run embedded etcd; the first bootstraps with cluster-init and the others join the same datastore, so one server can fail without losing quorum. Agents never run etcd and are labelled by hardware class. Storage is node-local through local-path, with durability supplied by etcd snapshots and off-box application backups rather than replication. Nothing is provisioned in this environment; the validation gate is what runs here.
