One address in front of many backends.

Relay reads a small services file, or the containers of the Docker daemon, and turns it into a routing table. A request to /service/path is sent to a healthy instance of that service, chosen in round-robin order. The proxy answers /health and an instance can be marked as unhealthy.

What it does

The capabilities

Every panel below is served by the real API of this project — nothing here is a mock-up.

⌗

Services file

ParseConfig reads the small services format of the project: a name and a list of instance URLs.

⇄

Round robin

Registry.Pick starts at an atomic counter and returns the next healthy instance of the service.

⛨

Reverse proxy

The path prefix is cut off and the request is sent to the backend with httputil.ReverseProxy.

✓

Health marks

Registry.Mark sets the health of one instance, so a broken backend is skipped.

◷

Docker discovery

DiscoverFromDocker turns the containers with the label foundev.service into services.

◑

Health endpoint

The proxy answers /health with ok, whatever the routing table holds.

Architecture

How it works

The program is one package main in proxy.go. ParseConfig reads the services file and fills a Registry, which holds a map of Service and the order the services were declared in. Registry.Pick walks the instances of a service, starting at an atomic counter, and returns the first healthy one, so the instances take turns. Registry.ServeHTTP splits the path into a service and the rest, and hands the request to the httputil.ReverseProxy of the chosen instance; that proxy is kept in a sync.Map so it is built once. DockerClient talks to the daemon over its unix socket and DiscoverFromDocker turns the containers that carry the label foundev.service into the same registry.
