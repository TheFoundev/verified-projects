The job that stops pinging is the job that matters.

A dead-man-switch service: every cron job pings a secret address, and when the ping does not come the check goes from up to late and then to down, and the alerts go out by email, by webhook or to the log.

What it does

The capabilities

Every panel below is served by the real API of this project — nothing here is a mock-up.

♥

A ping that says it is alive

Every job pings a secret address and the check knows the job is still running.

⏳

Late before down

The grace period gives the job a buffer, and only after the timeout does the check go down.

⇄

And up again

A ping that arrives in time brings the check back from late or down to up.

✉

Alerts where you look

The alerts go out by email, by webhook or to the log, once per transition.

⛭

Quiet for a while

A check can be muted until a moment in time, so a maintenance does not wake anybody.

⛁

Open pings, guarded writes

The pings and the status are open; the changes of a check need its own api token.

Architecture

How it works

A check holds the schedule, the grace period and the timeout, and its state moves from new to up to late to down and back to up when a ping arrives. The ping endpoint is open, because the uuid of the check is the secret, and the endpoints that change a check need the api token of that check. The background poller looks at the checks that are due, moves the ones that are late or down and dispatches the alerts over the channels of the check.

The API

Endpoints

MethodPathWhat it does
GET/api/v1/summaryThe state of the instance: the checks, their state and the pings that came in
GET/api/v1/checksThe checks of the instance (the read token is needed)
POST/api/v1/checksCreate a check (the write token is needed)
GET/api/v1/checks/{uuid}/statusThe state of one check, as JSON
GET/api/v1/checks/{uuid}/pingPing a check: the ping moves it to up and clears the counters
POST/api/v1/sessionSign in with the api token of a check
Quick start

Run it locally

# pip install -r requirements.txt
# python manage.py migrate     # the database of the checks
# python manage.py runserver   # the site and the API on http://127.0.0.1:8000
# python manage.py run_poller  # the background evaluator, in another terminal
# python manage.py test        # the test suite
