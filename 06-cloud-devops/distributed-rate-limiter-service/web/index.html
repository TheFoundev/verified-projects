One bucket per key, shared by every instance that has Redis.

Throttle gives every key a token bucket: a burst of requests is let through at once and the bucket refills at a fixed rate. The counters live in a Store, so the in-memory store limits one process while the Redis store lets several instances share one limit. A middleware answers 429 with the rate limit headers, the keys that are not used any more are swept away and the counters are exported in the Prometheus text format.

Architecture

How it works

limiter.go holds the limiter. NewLimiter takes a Store, a rate and a burst size; AllowAt asks the store for a token, RemainingAt reports the ones left and Sweep drops the keys that were not used for the ttl. KeyFor uses the X-API-Key header first and the forwarded address only when the proxy in front is trusted. Middleware answers 429 with Retry-After and the X-RateLimit headers, and Prometheus writes the counters in the text format. store.go holds the two stores: MemoryStore with a bucket per key behind a mutex, and RedisStore, which counts with INCR and sets the window with PEXPIRE over a small RESP client written for this project.
