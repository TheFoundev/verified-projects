Keep the objects, move the branches, read the workflow.

Anvil stores the objects of a repository the way git hashes them: the type, the size and the content of an object, separated by a null byte. A commit writes a blob for every file, a tree that lists them and the commit itself, and the branches point at the commits. The workflow file is read from its indentation, and the runner executes the steps of a job, skips the steps after a failing one and reports an action that is not implemented instead of pretending to have run it.

Architecture

How it works

repository.go holds the repository. gitObjectHash hashes an object the way git does, the type, the size and the content separated by a null byte, so the blobs, the trees and the commits have the same hashes as the objects of git. Repository.CommitAs stores a blob for every file, a tree with the hashes and the names sorted by name, and the commit object with its branch, its parent, its tree, its message, its author and its date, and then moves the branch to the new commit. Log returns the commits of a branch, newest first, Branches returns the branches and their commits, CreateBranch points a new branch at a commit, Checkout moves a branch to another commit and Diff returns the files that changed. Save and Load write the objects, the refs and the commits to a file. ParseWorkflow reads a small subset of YAML from the indentation: a job as a list entry or as a key, with run, uses, needs and env on the steps. Runner.Run walks the jobs and the steps, runs the command of a step in a shell, skips the steps after a failing one and skips the jobs whose job did not succeed. main.go commits two files and reads the sample workflow.
