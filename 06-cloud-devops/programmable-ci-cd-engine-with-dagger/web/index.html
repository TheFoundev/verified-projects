Run the steps in order, and keep the ones that already ran.

Ratchet takes a pipeline of steps with an image, a command and the steps it needs. Order puts the steps in dependency order and refuses an unknown dependency, a cycle and a step that is defined twice. Every step gets a digest that is built from its own content and from the digests of the steps it needs, so a change upstream changes the key of everything below it. A step whose digest is in the cache is skipped and reported as a cache hit.

What it does

The capabilities

Every panel below is served by the real API of this project — nothing here is a mock-up.

⌗

A step graph

A step has an image, a command, the steps it needs, retries, a timeout and its own environment.

⇄

Order and its three errors

Order refuses an unknown dependency, a cycle and a step that is defined twice.

◈

Content digests

digestOf hashes the step and the digests of the steps it needs, so a change upstream changes the key below it.

◑

Two executors

HostExecutor runs the command in a shell; RecordingExecutor only records what it would do.

▤

Two caches

MemoryCache keeps the digests in memory and FileCache writes one file per digest in a directory.

⛨

Retries and a timeout

A failing step is tried again as often as the step asks, and a step that runs too long fails.

Architecture

How it works

engine.go holds the engine. Step carries a name, an image, a command, the steps it needs, a number of retries, a timeout, its environment and the flag that keeps the value of a variable out of the log. Order walks the steps and returns them in dependency order; it refuses an unknown dependency, a cycle and a step that is defined twice. digestOf hashes the name, the image, the command, the digests of the steps it needs and the environment into a SHA-256. The Executor interface runs a step: HostExecutor runs the command with exec.CommandContext in a shell and captures the output, RecordingExecutor only records what it would do. The Cache interface keeps the digests: MemoryCache in memory and FileCache as one file per digest in a directory. Engine.Run walks the order, skips the steps whose digest is in the cache, retries a failing step and stops at the first step that fails. main.go reads the sample pipeline, the executor, the cache directory and the pipeline file from the command line. The steps run as recorded commands on the machine; there is no container engine behind them.
